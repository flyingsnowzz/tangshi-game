## 0. 一句话结论与推荐路线

| 路线 | 做法 | 性价比 | 建议 |
|---|---|---|---|
| A 只加宋词 | 复用现有 10 种题型，只扩题库 + 配图 | ★★★★★ | **P0 先做** |
| B 只加古文 | 新题型 + 新配图策略 + 新板块 | ★★☆ | 不建议单独先做 |
| C 宋词 + 古文全做 | 分轨 + 新题型 + 品牌升级 | ★★★★ | **本次选定，按 P0→P1→P2 分期** |

**核心判断**：现有工程天然装得下宋词（题库已有 `form` 字段、还混进了 2 首词），但**装不下古文**——古文是散文，不是「短句集合」，现有 10 种题型里 6 种会直接失效。所以宋词是"扩内容"，古文是"改产品"，两者工作量完全不是一个量级，必须分期。

## 1. PM 七问框架（决策自检）

| 问题 | 回答 |
|---|---|
| **Why 为什么做** | 产品叫"唐诗闯关"，但小初高必背古诗文里唐诗只是一部分。用户（家长/学生）要的是"语文古诗文背诵"整体解决方案，只做唐诗覆盖不全，留存和传播受限。 |
| **What 做什么** | 在现有 123 首唐诗基础上，接入课标内宋词约 40 首、文言文约 50 篇，配 `genre`（诗/词/文）分轨，古文新增专属题型，品牌升级为"古诗文闯关"。 |
| **Who 给谁做** | 小学高年级—初中的学生与家长（现有定位），古文部分主要服务初中—高中。 |
| **When 何时做** | 宋词 P0 先上（内容驱动，快）；古文 P1 需产品改造，排在宋词验证留存之后。 |

| **How 怎么衡量** | 宋词上线后：答题轮次 +、次日留存 +、分享率 +；古文上线后：初中/高中用户占比 +、关卡完成率。 |

## 4. 数据模型改造（必须先做，否则反复返工）

### 4.1 题库条目新增字段

```json
{
  "id": "c001",
  "title": "水调歌头·明月几时有",
  "author": "苏轼",
  "genre": "ci",          // 新增：shi=诗 / ci=词 / wen=文
  "dynasty": "宋",        // 新增：唐/宋/先秦/汉/魏晋/南北朝…
  "form": "词",           // 已有：保留（词牌/文言文体裁）
  "grade": "初中",        // 已有
  "difficulty": 3,
  "lines": ["明月几时有", "把酒问青天", "..."],   // 词：按句切分；文：按名句/短句切分
  "meaning": "...",
  "background": "...",
  "source": "义务课标2022" // 已有
}
```

### 4.2 关卡配置新增分轨

```json
{ "id": 41, "genre": "ci", "tier": 0, "name": "宋词初遇", "types": ["fill","next","image","author"], "count": 8, ... }
{ "id": 71, "genre": "wen", "tier": 0, "name": "古文启蒙", "types": ["trans","word","order","read"], "count": 8, ... }
```

### 4.3 出题引擎按文体放行题型

```js
// question-factory.js
var GENRE_TYPES = {
  shi: [fill, next, guess, match, image, order, author, title, feihua, odd],  // 现有 10 型全开
  ci:  [fill, next, guess, match, image, order, author, title, feihua, odd],  // 10 型全复用（词也是短句）
  wen: [fill, next, order, author, title, trans, word, read]                  // 去掉 image/feihua/guess/match/odd，加古文专属
};
```

**关键结论**：宋词侧 `question-factory.js` 一行不用改——词的"句"就是长短句，`lines` 切分照常工作。`guess` 的白话释义、`image` 的意象图、`feihua` 的飞花令字，对宋词全部成立。

## 5. 古文新题型设计（P1 核心工作量）

现有 10 型对散文失效的原因：`makeFill` 要求句长 ≥5 且按 2 字挖空、`makeNext` 要求相邻短句、`makeOrder` 要求连续 4 句——散文是长句，套上去就是"给半句话选下半句"，体验割裂。

| 新型 | 代号 | 交互 | 示例（《岳阳楼记》） | 可复用现有组件？ |
|---|---|---|---|---|
| 名句翻译 | `trans` | 四选一 | "先天下之忧而忧" → 选正确白话翻译 | ✅ 复用四选一 |
| 实词释义 | `word` | 四选一 | "予尝求古仁人之心" 的"尝" → 选"曾经" | ✅ 复用四选一 |
| 文意理解 | `read` | 四选一 | 给段落+问题，选理解正确项 | ✅ 复用四选一 |
| 名句补全 | `wf_fill` | 选字填空 | "□□天下之忧而忧" → 填"先" | ✅ 复用 fill 组件 |
| 文言断句 | `pause` | 点击加停顿符 | "先天下之忧而忧后天下之乐而乐" → 点出停顿 | ⚠️ 新交互（简单） |

**好消息**：5 种新题型里 4 种是"四选一"或"选字填空"，**页面交互组件 100% 复用**，只需在 `question-factory.js` 加 5 个 `makeXxx` 函数 + `quiz.wxml` 加一个断句分支。古文改造比想象中小。

## 6. 配图策略（三档，按文体分）

| 文体 | 策略 | 授权 | 成本 |
|---|---|---|---|
| 宋词 | **完全复用**现有摄影照流程，逐首按词句意象检索（明月/孤舟/江水/挑灯看剑） | CC0/PD | 低（流程现成） |
| 古文·有名句意象 | 只给高频名句配图（如"落霞与孤鹜齐飞"配秋水长天；"先天下之忧"配岳阳楼） | CC0/PD | 中 |
| 古文·纯议论/说理 | **不配图**，用"书法字签"兜底（大字名句 + 印章），避免"看图猜"类题型 | 无版权问题 | 低 |

> 延续既有红线：**图片必须与内容意象一致，禁止抽象无意义图**；古文实物图优先用实景照片（岳阳楼、醉翁亭、兰亭），拒绝乱配。

## 7. 关卡与品牌升级

### 7.1 分轨结构

```
古诗文闯关
├─ 唐诗（现有 123 首 / 40 关）      ← 不动，保护既有数据
├─ 宋词（新增 ~40 首 / 12 关 / 3 档） ← P0
└─ 古文（新增 ~50 篇 / 16 关 / 4 档） ← P1
```

- 首页加一个文体切换 Tab（唐诗 / 宋词 / 古文），默认唐诗，保护老用户习惯。
- 每轨独立难度与进度（`genre` 维度隔离），诗签册按文体分组。

### 7.2 品牌升级（放在最后一步 P2）

- 应用名：唐诗闯关 → **古诗文闯关**（WorkBuddy 应用卡改名）。
- 全站文案：`猜是哪句唐诗` → `猜是哪句诗词`（`question-factory.js` 里 `subText` 硬编码了"唐诗"字样，需一并改）。
- 分享卡片、首页标题、slogan 同步。
- ⚠️ 注意：改名会影响已发布应用卡的识别，建议 P0/P1 全部验证通过后再改。

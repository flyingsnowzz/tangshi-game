## A0. 绑定你自己的小程序（走正式账号，长期方案）

> 一次性操作，绑定后这台应用卡就对应 `wx266ad43142395b9f`，可以发体验版、以后提审正式版。

1. 打开「古诗文闯关」**应用卡预览** → 右上角**「分享」**。
2. **如果面板里已有一个「试用版 / 已发布」**（比如有效期到某日的试用码）——此时**看不到「绑定已有小程序」入口**，因为名额被试用版占着。先点面板右上**「解绑」**（官方说明：解绑就是用来更换所绑定小程序的），解绑后再进分享面板，就会出现「试用小程序 / 绑定已有小程序」两种选择。
   - 解绑会让原来那个试用码失效；既然要换正式账号，这是必经一步，不用担心。
3. 解绑后重新进「分享」→ 选**「绑定已有小程序」**（不是「试用小程序」）。
4. 按面板提示**用微信扫码授权**——用该小程序的管理员/运营者微信号扫（要能授权第三方平台）。
5. 授权成功后，面板「体验版」那一行变为可发布 → 点**发布**。
6. 发布成功后，该行最右**悬停二维码图标** → 下载小程序码。
7. **加体验成员**（关键，这样对方就不报「没有体验权限」）：
   - 登录 **mp.weixin.qq.com** → 该小程序 → **管理 → 成员管理 → 体验成员 → 添加**。
   - 填对方**微信号**搜索 → 勾选「体验者」权限 → 确认。立即生效。
   - 或者对方扫体验版码点「申请体验」，你在 mp 后台/微信通知里同意。
8. 对方重新扫体验版小程序码即可进入。

> 前置：正式小程序发体验版通常要求**账号已完成主体认证/基本配置**；若面板提示需认证，按提示在 mp 后台完成。规则以面板显示为准。
> 想换绑别的小程序：分享面板点**「解绑」**重来。解绑不影响代码，只换发布目标。

## A. 让对方体验（试用版，免账号快速方案）

你那张截图「抱歉，您不是当前小程序的体验者，没有体验的权限」= 对方微信不在**试用小程序**的体验者名单里。按下面顺序做：

### A1. 你这边：发布试用版 + 取码（一次性，或每次改代码后重做）

1. 打开「古诗文闯关」**应用卡预览**。
2. 点右上角**「分享」**图标（在**刷新**和**「⋯」**左边）。
3. 分享面板里找到**试用版**那一行：
   - 若显示未发布 → 选**「试用小程序」**，用微信**扫码创建**一次（无需注册账号、无需认证）。
   - 若已发布 → 直接下一步。
4. 发布成功后，该行最右侧的**二维码图标**会亮起 → **鼠标悬停** → 弹出小程序码 → 点**「下载」** → 发给对方。
   - 备用取码入口：**设置 > 数据管理 > 应用**，已发布小程序那一行也有二维码（只能下载）。
   - 注意：预览面板里的模拟手机**不是**扫码入口。
5. 有效期以面板上显示的「请在 X 月 X 日前发布使用」为准（微信规则会变，别记固定天数）。

### A2. 对方那边：扫码 + 申请体验

1. 对方用**微信**扫你发的小程序码。
2. 若弹出「没有体验权限」→ 点页面底部**「申请体验」**。

### A3. 你这边：批准（关键——入口在微信，不在 WorkBuddy）

1. 你自己的微信会收到一条**「服务通知」**，标题类似**「小程序体验成员申请」**。
2. 点进通知 → **同意**。
3. 让对方**重新扫一次**那个码，即可进入。

> **批准入口就在你的微信「服务通知」里**。你用的是试用小程序，**没有 mp 后台**，WorkBuddy 分享面板里也**没有**「批准体验者」按钮——别在那里找。
>
> **谁是管理员**：当初**扫码创建这个试用版的那个微信号**就是管理员，只有它能收到体验申请并批准。
> 如果不确定是哪个号：拿另一个微信扫码 → 点申请体验 → 哪个微信号收到了「小程序体验成员申请」，那个就是管理员号。以后就用它来创建/管理试用版。

### A4. 改了代码之后

改代码**不会**自动同步到线上。回到应用卡预览 → 右上角「分享」→ 对应版本行点**「更新」**重新发布 → 重新取码发给对方（旧码指向旧版本）。

## B. 一起开发（对方也要用 WorkBuddy）

### B1. 为什么不能「加开发者权限」

WorkBuddy 应用卡是**托管在你账号下的一张卡**，没有「把某人设为开发者」的开关。对方就在他自己电脑上用 WorkBuddy，两人各写各的、靠 **Git** 同步代码。对方体验的是**他自己那份代码生成的小程序**，跟你的应用卡互相独立——所以**根本不需要**成为你应用卡的体验者或开发者。

### B2. 一次性：建 Git 私有仓库（你做）

1. 在 **Gitee（国内快，推荐）** 或 **GitHub** 建一个**私有**仓库，例如 `tangshi-game`。
2. 本地这份代码已 `git init` 且已 commit（`b883d44`），工作区干净，还没 push。把远程加上推上去（**push 由你本人执行**）：

   ```bash
   cd /Users/zhanglei/WorkBuddy/2026-11-15-08-45-01/tangshi-game
   git remote add origin https://gitee.com/你的账号/tangshi-game.git
   git push -u origin master
   ```

3. 把仓库地址给对方。

### B3. 对方首次拉取 + 跑起来

```bash
git clone https://gitee.com/你的账号/tangshi-game.git
cd tangshi-game
```

对方打开自己的 WorkBuddy，新建任务，话术：

> 「我这个目录是一个已经写好的 WorkBuddy 原生小程序工程，请加载这个目录，不要重新搭骨架，直接跑原生校验并生成应用卡预览给我。」

把 clone 的 `tangshi-game` 目录作为任务工作目录 / 上传工程文件。WorkBuddy 会生成**属于对方自己的应用卡**。对方要体验，就在他自己那张卡上点「分享」→ 试用小程序 → 发布 → 取自己的码（走 A1/A2/A3，管理员是对方自己的微信）。

### B4. 日常协作

```bash
git pull                       # 开工前先拉
git add . && git commit -m "feat: 改了什么"
git push                       # 改完尽快推
```

黄金规则：先 pull 再改；别同时改同一文件；冲突了保留双方内容再 commit；对外发布的正式版本由你统一决定。

## C. 常见坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 对方扫码「没有体验权限」 | 不在体验者名单 | 走 A2/A3，对方申请 + 你在微信服务通知同意 |
| 你没收到体验申请 | 你不是创建试用版的那个微信号 | 确认管理员号（见 A3 末），用它重新创建/管理 |
| 在分享面板找不到「批准」按钮 | 试用小程序没有这个入口 | 批准只在微信服务通知里 |
| 对方看的是旧版本 | 改代码后没重新发布 | 回分享面板点「更新」，重新取码 |
| 想让对方改代码却找不到权限设置 | 应用卡没有开发者权限开关 | 走 B，用 Git + 对方自己的 WorkBuddy |
| 内置预览里一切正常，真机不行 | 预览器不走 wx 原生能力 | 一切以试用版/真机为准 |
